# Round 9 — Runtime validation prompt (fixes round)

You are validating the latest build of **Chronicles** (a visual-novel RPG built
on this Perchance generator). This round verifies the **three fixes** from the
round-8 findings, plus a quick regression sweep of the round-8 flows.

**Changes since round 8:**
1. **ORT proxy worker fixed.** The client-side RMBG-1.4 removal should now run
   for real on the platform (rounds 7–8: it never ran — the worker crashed at
   load with `no available backend found. ERR: [wasm] [object Event]`, so every
   sprite fell back to the platform's dirty removal). The Vite build now
   disables the modulepreload polyfill (`modulePreload: false`), which was
   killing the worker. Expect `model ready` + `inference done` on the platform.
2. **Fog canvas fixed.** The fog was rendering to a detached canvas (invisible).
   The PixiJS canvas is now appended inside the scene container — expect a
   transparent drifting haze over the scene frame.
3. **Sprite grounding changed (owner decision).** Sprites now generate on a
   **pure white background with the ground shadow baked into the image**, and
   the code-drawn shadow plane was removed from the stage. After removal the
   baked shadow stays with the sprite, so characters should read grounded
   wherever the generator placed their feet. The matte's dark-spill pass is off
   so the baked shadow survives. Prompt change busts the sprite cache —
   **sprites regenerate on this round** (intended; expect a slower first boot).

Do the checks **in order**, driving the actual UI (click, type, observe the DOM
and the console). The AI plugins are real here, so generations take time — the
loading indicators are part of what we validate. Report everything with
**console lines verbatim** (keep the `[rpg]` logs).

Before you start, read `src/README.md` for the project context and the
platform↔code mapping.

## 0. Upload check (do this FIRST)

- Confirm the workspace contains `src/rpg/build/chunks/` with the three.js,
  transformers.js and pixi chunks. If a chunk is missing, the generator is
  stuck with `Failed to fetch dynamically imported module: .../chunks/*.js` —
  STOP and report "upload incomplete — chunks/ missing".
- The local wasm asset (`assets/ort-wasm-simd-threaded.asyncify-*.wasm`) is
  intentionally NOT uploaded — the app pins ONNX Runtime to the jsdelivr CDN
  via `wasmPaths`. A 404 for that asset is a REGRESSION, not expected.

## 1. Boot & title (quick)

- Reload. Title renders (light paper look, "CHRONICLES", NEW GAME / LOAD GAME /
  SETTINGS / CREDITS / HELP). LOAD GAME disabled when no save exists
  (`aria-disabled`, click inert). Keyboard: arrows move the hand pointer,
  Enter/Space activate, Esc inert on the title.
- **Console at boot:** the `[rpg]` removal lines must appear —
  `proxy worker active (… wasmPaths=CDN)`, `model downloading (first visit
  ~45 MB)` → `model download complete` → **`model ready (… ms)`**.
  **There must be NO `no available backend found` / `[wasm] [object Event]` /
  `client-side removal failed` warnings.** This is the round-9 blocker gate.

## 2. Wizard → first real client-side removal (the big one)

- **NEW GAME** → name (e.g. "Arin") → **Next** → click an archetype. This
  triggers the **first real RMBG-1.4 removal on the platform**:
  - Loading UI: "Downloading AI model (first visit)…" with a RISING
    percentage (first visit), then "Removing background 1/1…", then the sprite
    preview. The UI must NOT freeze during download/inference (proxy worker).
  - Console: `model ready (… ms)` then **`inference done (… ms)`** and
    `cutout-cache: miss <id> → removing`. No fallback warning.
  - Network: wasm from
    `cdn.jsdelivr.net/npm/onnxruntime-web@1.26.0-dev.20260416-b7804b056c/dist/`
    (200, no 404); model files from huggingface.co (200).
- **Sprite quality (was never validated — RMBG never ran before):** the raw
  sprite is on a **pure white background** with a baked ground shadow; RMBG
  removes the white and keeps the character + shadow. Look closely at the
  wizard preview: clean cut-out (no mottle, no dark halo, no furry edges)? The
  **baked shadow visible under the character** (soft ellipse / one-direction
  shadow)? Black outline following the silhouette (no detached black blocks)?
  **Report-only:** does the outline ring wrap the baked shadow in an ugly way?
- **Next** → background (template or custom) → **Next** → review → **Create**.
  Expect the save to be created and the **game scene loads**.

## 3. Scene — fog + grounding (the other two fixes)

- After the scene loads, verify:
  - **Fog (was invisible — now mounted):** a transparent haze drifts over the
    scene frame. Take TWO screenshots a few seconds apart — the haze must
    differ slightly (it moves). The fog must NOT block clicks (pointer-events
    none) and must not affect HUD readability. Console must show no fog-related
    errors.
  - **Grounding (was floating):** both characters stand ON the ground with
    their **baked shadow** under them (part of the sprite image, not a code
    ellipse). NO separate dark ellipse drawn by the code (it was removed).
    Check near the feet: does the character touch the ground even if their
    feet are not at the bottom of the image?
- The narrator opening should play as before (2–3 sentences, Leave closes).

## 4. Dialogue quick regression (round-8 flows — spot-check only)
