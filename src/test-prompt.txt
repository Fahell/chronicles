Changes since round 5 (already in this build — verify them, do not report
them as new issues):
- RMBG inference now runs OFF the main thread via the ONNX Runtime proxy
  worker (`proxy=true`, `numThreads=1`). You should see the log
  `[rpg] bg-removal: proxy worker active (wasm proxy=true, numThreads=1)`.
  The UI must stay responsive (the loading screen animates) while the model
  works — the main thread is no longer blocked for minutes.
- The boot overlay is now an ANIMATED loading screen that reports live
  stages in the background: "Generating scene assets…", "Removing
  background…", "Polishing sprites…", etc. A discreet corner chip
  ("Removing background 1/2…") appears while removal runs.
- PROCESSED CUT-OUTS ARE CACHED: after the first removal, the cut-out is
  stored in IndexedDB (`cutouts` table). A reload serves it WITHOUT running
  inference — you should see `[rpg] cutout-cache: hit <id> (skip
  inference)` in the console and the reload must be FAST (seconds, not
  minutes).
- The plugin-removal FALLBACK (if the model CDN is blocked) is never cached:
  every reload re-attempts RMBG. If you see the fallback warning
  `bg-removal: client-side removal failed`, report it, reload, and confirm
  it is attempted again.
- The sprite background prompt was strengthened (solid pure black, no
  gradient/vignette/shadow) + a `negativePrompt`. Because the prompt changed,
  the sprite cache busted — the sprites REGENERATE this round on their
  pure-black backgrounds. The old dirty cut-outs must NOT come back.
