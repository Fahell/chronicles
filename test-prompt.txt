You are the runtime validation agent for this RPG generator. The AI text and
image plugins only execute inside the Perchance platform, and the generator

Before you start, read `src/README.md` for the project context and the
platform↔code mapping.

UPLOAD CHECK (do this first):
- Confirm the workspace contains `src/rpg/build/chunks/` with at least one
  `.js` file inside. The app lazy-loads three.js from that folder; if it is
  missing, the generator will be stuck on the "Generating scene…" overlay with
  a console error like:
  `TypeError: Failed to fetch dynamically imported module: .../chunks/three.module-*.js`
  If you see that error, STOP and report "upload incomplete — chunks/ missing"
  instead of testing further.

Changes since round 3 (already fixed in this build — verify them, do not
report them as new issues):
- Background removal is now PER-ASSET: only character sprites get it. The
  floor and backdrop are generated WITHOUT removeBackground, so the black
  sky/corrupted-backdrop issue is gone (round 3 forensics: 76.8% pure-black
  pixels with it on vs 0% without). NOTE: the old black floor/backdrop may be
  cached — if the floor/backdrop still look blackened, clear the IndexedDB
  cache and reload before judging.
- Character sprite prompts now ask for a SOLID PURE BLACK background (the
  easiest case for the plugin's background removal), and every portrait is
  post-processed by a client-side matte cleanup that trims semi-transparent
  fringe and near-black spill around the silhouette. Residual pixels are also
  discarded by the renderer (alphaTest), so sprites should no longer show
  faint rectangular edges or a mottled rim.
- Floor/backdrop are requested at landscape 768x512 and map 1:1 onto the 3:2
  frame (no stretch).
- Dialogue text is now PAGINATED (long replies split into pages with a "1/2"
  page indicator — the box never grows huge), and options are laid out in a
  horizontal grid that wraps instead of a vertical list. Enter/Space advance
  a page; Escape always exits the dialogue.
- The floor plane was widened and extended so its far edge reaches the
  backdrop plane: the perspective seam is gone — no more holes at the upper
  sides where the floor meets the backdrop.

- Report: does the page load? Is the letterbox frame correct (bars above and
  below, scene centered)? Any console errors (paste them verbatim)?

Expected generations (all via the image plugin, cached after first run):
- Floor: grassy meadow texture (pixel-art style), landscape 768x512.
- Backdrop: twilight landscape with a distant castle on the right and rocky
  spires on the left, landscape 768x512. It must NOT be blackened/corrupted.
- Player sprite: a protagonist character, portrait 2:3 (512x768), pixel-art
  style.
- Elder sprite: an elder character, portrait 2:3, pixel-art style.

- IMPORTANT — sprite matte: inspect the character sprites closely (zoom /
  sample pixels if you can). Expected: clean cutout silhouettes with NO faint
  rectangular box, NO mottled/dark rim around the figure. The background
  should be fully transparent (or, if the plugin left a black background, the

- Confirm all four assets generate and appear (floor under the characters,
  backdrop behind them, sprites standing on the floor at a sensible scale).
- Note: generation may take a while — do NOT treat a slow generation as a

- Report: how long did each generation take (approx.)? Did all assets apply
  correctly? Actual resolutions observed? Sprite edge quality (clean vs.

Look closely at where the floor meets the backdrop, especially the upper-left

--------------------------------------------------------------------------------
4. DIALOGUE FLOW (pagination + grid + choices + always-escape)
--------------------------------------------------------------------------------
Click the "Talk to the elder" button (top-left HUD).

Expected:
- The dialogue box appears at the bottom with speaker "Elder". While the AI
  text is being generated, a "thinking" indicator should be visible in the
  box.
- The AI text renders when ready. Because the prompt now asks for it, the
  response should usually include a `[choices]` block, which the app parses
  into option buttons.
- PAGINATION: if the reply is long, it should be split into pages with a page
  indicator (e.g. "1/2") and a Continue button — the box must NOT grow to fit
  the whole text at once. Continue (or Enter/Space) advances to the next page;
  options appear after the last page.
- OPTION LAYOUT: options should be arranged in a horizontal grid that wraps
  to a second line when there are many/long options — NOT a tall vertical
  list.
- Clicking an option ends the turn. If no options were offered, "Continue"
  advances and the box stays open until "Leave".
- The "Leave" button is ALWAYS present and ALWAYS ends the interaction
  (always-escape — the player can never get stuck in a dialogue).
- Keyboard: Escape closes the dialogue at any point; Enter/Space advance a
  page when one is shown.
- If you can force a text-generation failure (e.g., break the network), an
  error message with retry should appear instead of a silent hang.

Report: does the dialogue open? Is the loading indicator visible? Does
pagination work (page indicator, Continue)? Are options in a horizontal grid
that wraps? Do options work when present? Does "Leave" always close the box?
Do Escape/Enter behave as expected? Any error handling observed?
