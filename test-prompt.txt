You are the runtime validation agent for this RPG generator. The AI text and
image plugins only execute inside the Perchance platform, and the generator
runs in a cross-origin iframe — so you are the only one who can validate the
real plugin behavior. Local tests + CI are already green; your job is to
validate what only runs here: the real `generateImage` / `generateText` calls
and the client-side background-removal model.

Before you start, read `src/README.md` for the project context and the
platform↔code mapping.

UPLOAD CHECK (do this first):
- Confirm the workspace contains `src/rpg/build/chunks/` with the three.js
  AND the transformers.js chunks (at least two .js files: `three.module-*`
  and `transformers.web-*`). The app lazy-loads both; if a chunk is missing,
  the generator will be stuck on the loading overlay with a console error
  like `Failed to fetch dynamically imported module: .../chunks/*.js`.
  If you see that, STOP and report "upload incomplete — chunks/ missing".

Changes since round 4 (already fixed in this build — verify them, do not
report them as new issues):
- Character sprites are now removed in the BROWSER by RMBG-1.4 (IS-Net) via
  @huggingface/transformers + ONNX Runtime Web — NOT by the platform's
  removeBackground (which left dirty edges). The image plugin now generates
  sprites RAW (no background removal) on the solid-black background the
  prompts request; the client removes it.
- The removal model (~45 MB, quantized q8) downloads once at boot and is
  cached by the browser. A sprite generated before the model is ready simply
  waits for it. If the model CDN is unreachable, the app falls back to the
  platform's removeBackground (a warning appears in the console).
- Every sprite now has a BLACK OUTLINE (dilated silhouette plane behind the
  character) so it stands out against the scene.
- Detached removal specks are filtered out (sprite + outline) so the cut-outs
  are clean.

--------------------------------------------------------------------------------
Expected pipeline for the two character sprites (player, elder):
- The image plugin generates them RAW (on a solid black background).
- RMBG-1.4 runs in the browser and cuts the background out.
- The result: clean transparent cut-outs with NO black box, NO dirty mottled
  edges, NO white/grey speckles floating around the figure.

Check and report:
- Look closely at both sprites (zoom/sample pixels if you can). Are the
  edges clean? Any residual background remnants (black spill, bright
  speckles, semi-transparent fringe)?
- Timing: how long did the model take to load (first boot)? How long per
  sprite (inference)? Use the Network tab to confirm the ~45 MB model
  download (huggingface.co) and whether it was served from cache on reload.
- The black outline: is the border visible, clean, and following the
  silhouette? Are there any detached black blocks floating near the sprites?
- If the fallback fired (console warning "bg-removal: client-side removal
  failed"), report it — the model CDN may be blocked on the platform.
